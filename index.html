q4 · ¿Qué es un autómata finito?

    
Una máquina con memoria mínima: solo recuerda su estado

    

      

        
Lee símbolos uno por uno. Según el estado en el que está y el símbolo que lee, salta a otro estado. Nada más.

q11 · Análisis léxico

    
El escáner convierte caracteres en tokens

    

      
Token la categoría
Un par ⟨nombre, atributo⟩ que recibe el parser.
⟨ID, 1⟩ · ⟨NUM, 18⟩

      
Lexema el texto real
La secuencia de caracteres que coincidió.
edad · 18 · >=

      
Patrón la regla
Describe la forma de los lexemas: una expresión regular.
[a-zA-Z_][a-zA-Z0-9_]*

    

    

    

      
Los espacios y comentarios se descartan: el parser nunca los ve. Cada identificador nuevo va a la tabla de símbolos, y el token guarda su posición. Además, el lexer lleva la cuenta de línea y columna para reportar errores.

q12 · Las dos reglas de oro del lexer

    
¿Cómo decide dónde corta una palabra?

    

      
1El lexema más largo gana
Maximal munch: el lexer sigue leyendo mientras el autómata pueda avanzar, y se queda con el último estado de aceptación. >= es un solo token, no > y =.

      
2En empate, gana la prioridad
if coincide con PALABRA_CLAVE y con ID (misma longitud): gana la regla con mayor prioridad. Pero iffy es más largo como ID, así que es ID.

q14 · Juego: ¿quién atrapa el error?

    
No todos los errores son léxicos 

    

    

      
Recuperación en modo pánico: cuando el lexer encuentra algo que no reconoce, reporta el error con línea y columna, descarta caracteres hasta poder formar un token válido y sigue leyendo. Así puede reportar varios errores en una sola compilación.

    

  







  

    
q15 · ¿Y el autocorrector?

    
Un diccionario también es un autómata (un trie)

    

      

        

        
        

        

        
Cada letra es una transición. Si no existe la transición, caes al estado de error ∅ y entonces se buscan las palabras a menor distancia de edición (insertar, borrar, cambiar o intercambiar letras). Los autómatas de Levenshtein (Schulz y Mihov, 2002) hacen esta búsqueda muy rápido.

      

      

    

  







  

    
q16 · En la vida real

    
Nadie dibuja el autómata a mano: lo generan herramientas

    

      
Flex (C)


%%
"if"|"else"|"while"      { return KEYWORD; }
[a-zA-Z_][a-zA-Z0-9_]*   { return ID; }
[0-9]+("."[0-9]+)?       { return NUM; }
">="|"<="|"=="|"!="      { return RELOP; }
"//".*                   { /* comentario: ignorar */ }
[ \t\n]+                 { /* espacios: ignorar */ }
.                        { error("carácter inválido"); }
%%

      

      
ANTLR 4 (Java, Python, C#…)


lexer grammar MiniLexer;

IF      : 'if' ;
WHILE   : 'while' ;
ID      : [a-zA-Z_] [a-zA-Z0-9_]* ;
NUM     : [0-9]+ ('.' [0-9]+)? ;
GE      : '>=' ;
COMMENT : '//' ~[\r\n]* -> skip ;
WS      : [ \t\r\n]+   -> skip ;

      

    

    

      
¿Qué generan? Una tabla de transiciones (el AFD) y un bucle que la recorre. Es lo mismo que hicimos en q10.

      
¿Y los compiladores grandes? GCC, Clang y Go usan lexers escritos a mano por velocidad y mejores mensajes de error… pero por dentro siguen siendo autómatas: un switch por estado.

      
¿Dónde más? El resaltado de sintaxis de tu editor, grep, la validación de formularios y los motores de expresiones regulares.

    

  







  

    
q17 · Entonces…

    
¿Cómo sabe la computadora que escribiste mal una palabra?

    
    
      
  • 1Un autómata finito es una máquina que solo recuerda su estado: torniquetes, semáforos, expendedoras… y compiladores.
    • 
      
  • 2Cada tipo de token se describe con una expresión regular, que se convierte en AFN (Thompson), luego en AFD (subconjuntos) y se minimiza.
    • 
      
  • 3El lexer recorre ese AFD, aplica «el lexema más largo» y la prioridad, y entrega tokens al parser.
    • 
      
  • 4Si el autómata no puede formar ningún token, es un error léxico: @, cadenas sin cerrar, 3.14.15.
    • 
    

    
La computadora no «sabe» nada: un autómata intenta reconocer tu palabra. Si cae al estado de error, ahí está el error léxico. Y si whlie parece un identificador válido, lo atrapan el parser, el análisis semántico… o un autocorrector, que también es un autómata.
